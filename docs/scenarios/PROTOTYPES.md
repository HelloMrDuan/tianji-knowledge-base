# 十个核心场景：输入与输出原型

完整机器样例见 `config/scenarios/prototypes.json`；设计板提供十一入口切换，事业/财运同一份核心报告。输入均为虚构/固定示例，不是用户资料；所有指标缺口显示 unavailable/null，没有编造指数、吉日或趋势。两份结构样例实际运行过相同确定性代码，执行出处见 capability_snapshot；它们不代表已部署场景接口。

统一七段输出：综合指数、当前趋势、关键时间、有利因素、风险提醒、典籍依据、不确定性。另有概要、已算事实、下一步、历史版本和 AI 状态。`risk_reminders` 当前内容主要为能力限制，不能被读成“未来将遇到的风险”。

| 原型 | 输入界面 | 结果主文／模块 | 个别失败与验收 |
| --- | --- | --- | --- |
| 今日运势 | 已保存出生档案/精度＋2026-10-04；北京时间只读 | “个人当天趋势尚不可算”；指数/趋势/关键时间为空，显示缺八字流日和判读 | 缺档案先说明依赖不收资料；当天刷新不重算新运势；时辰未知不猜 |
| 本周运势 | 出生档案＋2026-09-28 周一；范围至 10-05 00:00 exclusive | 预留本周主题、分段、关注因素、回顾；当前全部计算性结论 unavailable | 跨月/节气周保留多段；不是每日假分的平均；换周生成新周期 |
| 本月运势 | 出生档案＋2026-10；10-01→11-01 | 预留月主题/节气分段；当前提示公历阅读窗≠干支月界 | 月初跨节气不误用公历月柱；只有月级证据不输出精确日时 |
| 2026 年运势 | 出生档案＋year=2026；默认值可改未来其他年 | 预留年度主题、运期交界、分月因素；当前无大运/流年所以 blocked | 年界与阅读窗口分开；不以生肖配今年生肖凑分；不硬编码全年吉凶 |
| 桃花姻缘 | 出生档案＋10 月关注窗口＋可选关系状态 | 预留关系关注点、条件成立/冲突、时间精度、出处；当前“不足以判断关系趋势” | 只有咸池命中不能给恋爱概率；夫妻宫位置只在结构折叠层；未提供状态不推断单身 |
| 事业财运 | 出生档案＋career/wealth 视图＋时间窗＋可选具体事项 | 同一报告按事业因素或财务因素阅读；当前缺喜忌/时序/场景证据，趋势与收益不输出 | 切换 view 不重排、不改变共有结论；没有具体占问不调用奇门；不输出投资收益率 |
| 缘分合盘 | A、B 资料分栏，各有精度、版本、同意；主题可选沟通/关系 | 预留双方关系条件、差异与方向；当前维度 a/b/relation 都为 null，匹配分 null | 一人缺时辰保留影响说明；对称关系换人一致；不从年生肖一个维度给完整合盘 |
| 一事占问 | 一件事、记录时刻；有投掷填六次 6/7/8/9，自下而上；否则确认时盘建议 | 固定真实样例：“乾为天，第六爻变化后为泽天夬”，随后说明不能由此判断合作成败；不是裸规则列表 | 六次值缺一不提交、不 random；拒绝 unsupported variant；AI disabled 时仍显示结构与必要依据 |
| AI 解梦 | 梦境文字、可选醒来情绪/日期/个人联想；不问出生时刻 | 示例“梦见沿河行走”仅作为输入；当前无审核语料，传统象征/AI解释 unavailable | 检索不到就显示缺证；“没梦到蛇”不得检索成“梦到蛇”；来源冲突并列；不虚构《周公解梦》段落 |
| 人生全盘 | 出生档案＋关注主题；空间方向仅可选分支 | 固定紫微结构档案可定位“关系资料在夫妻宫、事业在官禄、财务在财帛”；先显示可读主题，再折叠原盘；无完整人生走势 | 闰月拒绝基本紫微 datetime 模块；大限流年缺失不补；四化 D 不能升为已核古典结论 |

## 一事占问固定实际样例

输入占时 `2026-10-04T12:00:00+08:00`，六次值 `[7,7,7,7,7,9]`。使用 `jingfang-eight-palaces-v1`，结构为乾为天→泽天夬，变化位置为上爻。报告前三条为“本次卦象”“变化位置”“变化后结构”，绑定 `liuyao.phase2.motion/palace`；附必要来源片段。当前趋势、成功率、应期和有利因素仍 unavailable。下一步为核对记录/查看结构依据，而非诱导把未判读结构当作决策结论。

## 人生基础档案固定实际样例

输入 `1999-02-16T00:00:00+08:00`，明确紫微 year_boundary=lunar-new-year。`quanshu-lunar-iztro-mutagen-v1` 的宫位结果中：夫妻宫在子、官禄在午、财帛在戌。这只定位已核结构信息，没有“婚姻幸福”“官运好”“财运旺”的判读。样例保留四化计算的 D 软件说明，主报告不拿四化造综合指数。

## 复访与合盘原型数据

日/周/月记录的设计 cache key 含 owner、资料版本、周期、registry/engine/rule/聚合版本及输入摘要；历史服务 supported_now=false。报告回顾分“当时计算结果”“后来版本变化”“用户自填反馈”三类，不把用户感受当预测准确性证明。

合盘示例 A 为上述出生资料，B 为虚构 `2000-06-01T12:00:00+08:00`，只展示两人输入结构；没有运行八字/成对规则，三个比较维度日支关系、五行关系、运期对照都为空，必须等待真实依赖。既不套默认 60 分，也不以两个紫微宫位碰巧相同判为有缘。

共同验收还包括：修改样例输入后不得继续显示旧样例为新计算；设计板的字段只读，报告固定，明确没有提交/保存；未核 AI 不得生成；空指数显示“—”而非 0；有引用但无判读证据时不生成有利因素。
