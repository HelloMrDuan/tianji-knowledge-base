# 首页与 Scenario 管理信息架构

使用 frontend-design 的 Editorial / Magazine 方向：保留天机纸色、青墨与铜色印记，视觉锚点改为“围绕一件生活问题展开的报告”，不让术数卡片决定首页。此阶段只有单页设计板，不改 PR #87 的业务页面，不新增十套真实页面。

## 前台层级

桌面主导航：**首页｜场景报告｜我的记录｜专业排盘**；手机底部：**首页｜场景｜记录｜我的**，专业排盘在“我的/更多”的二级入口。收藏并入记录；方法术语和盘面在报告内展开，不占首屏第一视觉层。

首页拟定阅读顺序：

1. 场景首屏：“今天，你想看哪一件事？”主行动“一事占问”；辅助“关系与姻缘”“事业与财运”。在真实部署之前不提供可用假象；当前展示设计预览，不能提交个人资料。数据为空的运势区域无随机数字、红绿曲线或默认好日子。
2. 时间入口：今日／本周／本月／2026。绑定同一出生档案和当前查看窗口；没有档案提示“先了解所需资料”，依赖缺失显示“功能准备中”且不先收出生资料。今后上线后，“继续看本周”复用已存报告，不换个随机分数。
3. 生活主题：桃花姻缘、事业前程、财运分析、缘分合盘、一事占问、AI 解梦、人生全盘。事业/财运可分卡，依赖同一核心场景和同一底层 run。每卡记录标题、可读结果、资料成本、开放状态与限制；不堆术数标签。
4. 我的记录：用户真实记录存在后才显示“继续上次报告”“本周回顾”“对比资料版本”；未实现存储时显示设计空态，不能拿 DEMO 历史当用户记录。
5. “为什么这份报告可信”：展示计算、规则、出处、限制四步；链接到本份报告必要证据。来源仍 C/D，不能写“权威已验证人生预测”。
6. 专业排盘二级入口：八字、六爻、奇门、紫微、六壬、周易、风水全部保留。八字标“待接入”；每个入口说明实际 variant 和范围。不会删除已有专业功能，也不把待接入八字页面当 engine。

未来路由规划：`/scenarios/today`、`/week`、`/month`、`/2026`、`/romance`、`/career`、`/wealth`、`/compatibility`、`/question`、`/dream`、`/life`；它们尚未实现。专业入口规划 `/professional`，再按 engine 路由。PR #87 旧 `/liuyao` 等地址需要明确重定向方案；保留其含义和已有分享链接，迁移不能把历史六爻报告重解释为新场景。

## 输入与报告体验

场景先解释能回答的范围，再决定收哪些资料。出生档案只录一次并版本化；所有时区固定北京时间，年界/日界属于方法设置，不能伪装成时区选择。梦境只收梦境内容；一事占问默认不收出生资料；合盘对两人分别说明保存和授权。

报告主视图显示场景主题、能回答/不能回答、聚合因素和下一步。盘面、规则 ID、trace 放折叠层；典籍依据保留必要片段、出处、等级和限制。缺关键依赖：整份完整报告 blocked；可用结构：显式“部分参考”，不能套完整报告标题。AI 不可用时依旧看固定模板和事实，不出现假 AI 气泡。

综合指数当前显示“暂无可核指数”，当前趋势/关键时点分别显示缺失原因。设计板不会伪画曲线、幸运色/数字/方位或夫妻匹配分数。用户自填计划可以显示“你的计划”，不可混入“系统预测”。

## 后台 Scenario 管理

在 PR #87 静态后台导航设计上增加独立 **Scenario 管理**，拟议 `/admin/scenarios`，当前只有设计字段，没有真实管理接口/鉴权/发布动作。

| 工作区 | 配置字段 | 必须阻止的配置 |
| --- | --- | --- |
| 场景列表 | scenario_id、11 个入口/10 个核心、视图、成熟度、缺口、目标 mode、开放状态、依赖版本 | 把有页面/有 RAG 当成已可执行；以展示状态覆盖服务端资格 |
| 输入契约 | 字段/条件必填/资料精度/双人输入/北京时间/时间窗 | 缺时辰补中午；出生与占时混用；收集不用的经度/姓名 |
| Engine 计划 | required/supporting/conditional、实际 capabilities、variant、分支条件、超时与部分失败策略 | 任意 provider URL、跨派 fallback、未注册 bazi、生产相对元运 |
| 规则与 Evidence | 结构与场景规则分栏、原文定位、来源等级/血缘、审核、冲突、影响模块 | 引用存在但不支持结论；D 升 A/B；quarantine 用作已核正文 |
| 聚合与模板 | 因子/事实指针/权重依据/指标策略版本/显示精度、文案稿、null 文案、视图映射 | 默认 60 分；空证据词句；模板自行加吉凶/概率/应期 |
| 预览与验收 | 固定案例、缺依赖、时间边界、资料精度、双人互换、冲突/注入、模板输出 diff | 手改 oracle 来过测试；fixture 被称作真实模型通过 |
| 开放与审计 | draft→validated→limited_production/research；actor/版本/hash/原因/回滚 | 设计板按钮等于真实发布；AI 随场景开关自动开启 |

拟议权限：产品编辑可改输入/文案 draft；算法维护可登记已审 provider/variant；资料审核可登记 Evidence；发布负责人依据验收变更有限生产状态；AI 资格为独立审核记录，不能产品编辑手动打勾。后台无真实身份和服务端权限前，禁止接入真实 birth/dream/history 原文。

版本修改先 clone draft，不覆盖已发布 registry；规则/Evidence/schema/模板任一改变都需要新版本与受影响场景验收。发布门禁输出具体 blocker：未注册引擎、场景规则空、来源未审核、聚合不可证、固定案例失败、缺权限服务。完整预测报告和有限结构版应分别声明 scope，不能用同一开关偷换。

文案模板示例：`本次结构为 {{fact.original_name}}，{{fact.changing_lines}} 发生变化。{{limitation}}`；变量只能引用已审事实/限制。格式内容不自动进入 AI，也不自动授予权威等级。
