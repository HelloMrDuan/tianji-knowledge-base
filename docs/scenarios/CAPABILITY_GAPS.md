共六个注册 engine、37 条执行规则、28 个 Golden Cases。Phase1 来源为 A=0、B=0、C=87、D=6，独立性尚未证实的重复版本不升等级。执行关系已验证不等于对现实事件的预测有验证。`config/phase2_rule_promotions.json` 也明确只晋级计算关系，不晋级吉凶、跨派结论或来源等级。

## 八字：先做可审的执行契约，再做场景结论

| 阶段 | 现有资产 | 必须补齐 | 通过条件 |
| --- | --- | --- | --- |
| B0 输入与历法 | lunar-python==1.4.8、calendar()、干支循环、五鼠遁 | 八字年界/月界/换日/时干耦合的明确 variant；出生时刻精度；农历合法转换；不悄悄用真太阳时 | 立春/十二节两侧、23/00 点、闰日/闰月、1900/2099 边界的独立固定预期；拒绝未知时辰完整四柱 |
| B1 四柱与结构 | foundations_v1.json 十神/藏干、干支合冲表 | bazi PROVIDER、execution contract、规则 IDs、EvidenceResolver 接入、十神/藏干/合冲的纯函数和 trace | 网关/类型/schema/输入边界一致；每条关系可追到核过的原典段落；不直接用 60/30/10 藏干权重 |
| B2 起运与运期 | dayun_v1.json 顺逆、节/天数÷3 的现代实现说明 | 精确到前/后“节”而非泛“节气”；起运时间单位、舍入、顺逆性别口径；大小运与流年/月/日联动 | 跨节、顺逆、同一时刻两种边界、交运前后与持续区间固定案例；缺少传统性别口径时不猜顺逆 |
| B3 解释条件 | 三本已整理八字古籍；21 项 legacy 神煞 | 旺衰/格局/喜忌、桃花/财官印食适用条件、反例、冲突记录、可执行的场景规则 | 每条结论声明适用条件和依据；神煞仅旁证；无法裁定喜忌保留 null/research；不得自动晋级三命 |
| B4 合盘与聚合 | hehun_rules_v1.json 为开源评分说明 | 双人契约、成对/方向关系、输入版本与对称性、独立合盘资料、聚合权重依据 | A/B 互换的对称关系一致、方向关系翻转但不混主客；缺一人时辰拒绝完整报告；禁止默认 60 分 |

**calendar() 输出四个干支不等于八字产品完成。** 当前函数没有八字专属 Evidence/Golden/运期执行契约；必须把可复用历法作为 provider 依赖登记，不能仅把返回字段改名成“八字引擎”。`data/canonical/bazi/*_v1.json` 和 `yinyuan/hehun_rules_v1.json` 属旧 schema 0.1 的整理数据，不是六域 Phase2 execution contract；已有三本古籍文本也不自动转成可执行喜忌规则。

出生地/经度不是当前必需输入，避免收集不使用的资料。国内时区固定；真太阳时暂不支持，未来作为另一个明确研究 variant，不悄悄替换用户时刻。未知时辰允许保存不完整档案，完整时柱/起运/紫微盘/合盘相应模块 unavailable；用户不能被诱导随意填 12:00。

## 新知识库与研究范围

- 梦境：仓库无独立 dream Canonical/执行域。需资料授权/公版证明、原文/整理解释分层、象征词、上下文、否定和情绪词、出处定位、证据等级、冲突与 RAG 检索反例。梦境场景没有 chart、RuleMatch 盘面或确定性预测。
- 场景判读：桃花时序、事业/财务因素、合盘成对规则、周/月/年聚合证据均需补充。不能把条目名“桃花”“财帛”“官禄”当作已经核定的产品推论。
- 研究：旺衰/喜忌和跨流派冲突尚未裁定的分支、紫微 D 四化、绝对元运、未经复核的梦境 AI 解释均有明确 research/未验证标识。新聚合无法把各引擎的 C/D 合成 A/B。
- AI：PR #88 当前模型单例均未合格；既有六域解释 prompt 不能直接套作 scenario prompt。场景 AI 需聚合上下文契约和独立完整评测/人工复核，六域未来合格也不自动授予场景资格。
