# Scenario Runtime API

产品层不直接让用户选择术数算法。Scenario Engine 负责把场景映射到已审核的确定性能力，同时保持能力边界。

## Endpoints

- `GET /api/v1/scenarios`：返回场景注册表、开放状态与依赖。
- `POST /api/v1/scenarios/execute`：执行已实现的场景。

请求：

```json
{
  "scenario_id": "yearly",
  "input": {
    "birth_value": "2000-01-07T12:00:00+08:00",
    "target_year": 2026
  }
}
```

当前可执行场景：

| scenario_id | 状态 | 对外状态 | 说明 |
|---|---|---|---|
| bazi-profile | production | 已开放 | 四柱、日主、十神、藏干 |
| question | production | 已开放 | 六爻确定性盘面、规则、Evidence、Trace |
| daily | production_limited | 每日结构内测 | 目标日干支 + 日干十神 + 两套咸池目标支日级命中 |
| weekly | production_limited | 周结构内测 | 周一至周日 7 个日级结构 + 十神组频次 + 咸池命中日期 |
| monthly | production_limited | 月结构内测 | 目标公历月全部日级结构 + 十神组频次 + 咸池命中日期 |
| yearly | production_limited | 暂不公开自动解释 | 原局 + 目标干支年 + 流年天干十神结构 |
| romance | production_limited | 暂不公开婚恋解释 | 年支/日支分别起查的咸池目标支、原局命中与目标年份激活 |
| career | production_limited | 暂不公开事业财运解释 | 财星、官杀、食伤、印星、比劫位置聚合 + 目标年天干十神 |
| compatibility | production_limited | 合盘结构内测 | 双人四柱并列 + 双向日主十神 + 双向咸池目标结构匹配 |
| life | production_limited | 总览内测 | 聚合八字基础、年度、桃花、事业财运四个已验证结构场景 |

其余未实现场景仍返回注册状态，但执行请求会 fail closed。

## yearly 当前边界

`yearly` 不是“年度吉凶报告”。

它当前只组合：

1. 已审核的八字结构引擎；
2. pinned `lunar-python==1.4.8` 年干支；
3. 已审核十神规则。

目标年份使用 7 月 1 日作为稳定的干支年取样点，避免把公历 1 月 1 日误当作传统干支年边界；响应会明确返回该约定。

当前不输出：

- 旺衰
- 喜用神
- 格局
- 流年吉凶
- 桃花吉凶
- 事业/财富评分
- 健康判断
- 事件应期

AI 不参与 Scenario Engine 的确定性计算。


## romance 当前边界

`romance` 当前不是完整“桃花姻缘报告”。

它只执行已经审核并进入 Phase 2 的 `bazi.phase2.xianchi_lookup`：

- 年支作为基准：单独返回一组目标支；
- 日支作为基准：单独返回一组目标支；
- 不把两者合并成“唯一正确流派”；
- 检查原局四支是否出现对应目标支；
- 检查目标年份地支是否恰好等于对应目标支。

命中只表示固定查表结构成立。当前明确不输出：

- 桃花旺/弱评分；
- 恋爱是否发生；
- 婚姻好坏；
- 正缘时间；
- 异性缘性格断语；
- 疾病、酒色等古籍断语；
- 配偶星、夫妻宫、旺衰喜忌、紫微等综合判断。

《三命通会》相关纳音附加条件仍未进入自动规则。AI 不参与计算。


## career 当前边界

`career` 当前只做“事业财运结构”，不是事业/财富吉凶报告。

它复用已经验证的十神与藏干规则，把原局中的：

- 财星：正财、偏财；
- 官杀：正官、七杀；
- 食伤：食神、伤官；
- 印星：正印、偏印；
- 比劫：比肩、劫财；

按“天干明见 / 地支藏干”记录位置与数量，并计算目标年份天干相对日主的十神。

数量只是位置统计，不代表强弱，更不是评分。当前不输出：

- 升职/跳槽结论；
- 赚钱/破财结论；
- 财富金额或等级；
- 投资建议；
- 行业推荐；
- 事业/财运指数；
- 旺衰、格局、喜用神、大运应期。

AI 不参与计算。


## life 当前边界

`life` 是“人生结构总览”，不是完整人生预测。

同一次输入只做聚合，不创建新的命理规则：

1. 八字基础档案；
2. 目标年度结构；
3. 桃花/咸池结构；
4. 事业财运结构。

服务端额外生成四条 deterministic highlights，用于前台快速阅读；每一条都只复述上述结构事实，不含模型生成内容。

当前不会在总览层新增：

- 吉凶评分；
- 人生等级；
- 正缘/结婚年份；
- 升职、收入或投资判断；
- 健康结论；
- 性格标签；
- 事件应期。

`rule_matches` 与 `trace` 保留 `scenario_section`，便于前台和后台追溯每条总览信息来自哪个子场景。Evidence 按 ID 去重。AI 不参与计算。


## daily 当前边界

`daily` 用于每日回访，但当前名称是“今日结构”，不是完整“今日运势”。

输入出生时间与目标日期后，它只组合已经验证的：

1. pinned 日历适配器得到目标日干支；
2. `bazi.phase2.ten_gods` 计算目标日天干相对日主的十神；
3. `bazi.phase2.xianchi_lookup` 分别检查年支/日支两套咸池目标是否被当日地支命中。

它不会把这些结构信号换算成：

- 好运/坏运；
- 宜/忌；
- 财运、事业、感情或健康分数；
- 今天一定发生的事件；
- 投资、医疗、法律或安全建议。

前端可将用户在“人生总览”里填写的出生资料保存在本地浏览器，第二天打开时直接复用；服务端不依赖该本地存储。AI 不参与计算。


## weekly 当前边界

`weekly` 以 `anchor_date` 所在的北京时间自然周为范围，固定周一至周日，共 7 天。

每一天复用与 `daily` 相同的已验证能力：

- 日干支；
- 日干相对日主的十神；
- 十神结构组；
- 年支/日支两套咸池目标是否被当日地支命中。

周汇总只统计十神结构组出现次数以及咸池命中日期，不解释成“本周财运/桃花/工作运更旺”。

## monthly 当前边界

`monthly` 当前按公历自然月展开全部日期，例如 2026-10 共 31 天。

它返回：

- 每日干支、十神结构组与咸池命中；
- 五类结构组在该月出现的日期频次；
- 咸池结构命中日期列表。

这里的“月”是产品浏览窗口，不声称等同于传统命理的节气流月。完整流月体系仍需独立证据与规则裁定。

weekly / monthly 都不输出：

- 吉凶分数；
- 宜忌；
- 收益或投资建议；
- 健康判断；
- 感情事件预测；
- 任何“某天一定发生”的断言。

AI 不参与计算。


## compatibility 当前边界

`compatibility` 是“双人结构合盘”，不是缘分评分器。

它输入两个人的出生时间，分别运行已经验证的八字生产链，然后只做两类跨人对照：

1. A 的日主看 B 的日主是什么十神；B 的日主看 A 的日主是什么十神；
2. A 的年支/日支咸池目标分别检查 B 的年支/日支是否命中；反向同样计算。

双向分别展示，不把任意一方视角偷换成唯一结论。

当前不输出：

- 缘分百分比；
- 配对分数；
- “适合/不适合”；
- 正缘/结婚年份；
- 分手风险；
- 谁更爱谁、谁克谁等关系判断；
- 现实情感建议。

夫妻宫、配偶星、合冲刑害、旺衰喜忌、大运流年、紫微交叉等尚未进入本场景。AI 不参与计算。
