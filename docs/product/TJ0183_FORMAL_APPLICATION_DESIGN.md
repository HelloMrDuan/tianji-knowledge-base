## 二、应用管线规约

### 2.1 形态与坐标系

应用批取**单批两阶段**形态（审定点 AP1）：一个应用批、一份
应用报告、一次冻结校验；018-H 路线备忘的第 2/3 步完整保留为
批内两阶段。坐标系四套：S0 快照坐标（既有校勘记累计 383 条
与归因位点所在）、S1 PUA 后坐标（与 S0 全等长、位置恒等，
偏移直接互译，S1 不单独登记为工件）、S2 基线坐标（候选
offset_basis 所在）、S3 全应用坐标。坐标互译只经 origin 位点
图（E0273 同机械），禁止手算偏移。

### 2.2 阶段一（PUA）

执行器 = 仓库脚本 `scripts/apply_pua_collation.py` 原样。语义
要点（脚本实测）：仅 confirmed 行参与；统一映射逐码位**先验
计数**——实际出现次数须与登记 count 逐一相等，否则以 source
drift fail-hard；语境映射逐规则锚串恰 1 次、合计须等于登记
count 且字形零残留；替换字含 PUA、码位/字形不自洽、重复映射
均 fail-hard。阶段输出校验：PUA 残留 0、字数 461,157
（等长不变量）、SHA256 == S1 钉值 `b4f196f2…`。

### 2.3 阶段二（文本订正）

执行器 = 仓库脚本 `scripts/apply_sanming_text_collation.py`
原样，文件序 ocr-001..603 即应用序，不得重排、并行或跳条。
语义要点：仅 confirmed（实测 603/603）；old/new 不得含
PUA（脚本以此强制阶段顺序）；逐条轮次校验 old 恰出现 1 次
——链式依赖 25 条的合法性正建立在此条上，依赖只经文件序
在先条目满足；目标预存校验：new 已预存且未登记豁免即
fail-hard，豁免登记与使用都必须恰为 **{ocr-022}** 一条。
**444 检查点**：ocr-444 应用毕立即校验中间文本 SHA256 ==
S2 钉值 `db8618c9…`，把应用批与重锚证据链钉在一起。终局
校验：603/603、SHA256 == S3 钉值 `a89c0b5d…`、PUA 0、
残余「防」769、□ 2。

### 2.4 应用记录与报告字段

逐条记录：seq、correction_id、位点偏移（该条轮次的当前文本
坐标）、old/new 的 SHA256、应用前后各 ±32 字语境的 SHA256、
len_delta；链式依赖条目另记材料依赖 id（与 E0265 归因登记
对账）。报告含：冻结校验结果（五文件逐一）、阶段一逐码位
记录与进出哈希、444 检查点哈希、阶段二逐条记录与豁免使用
集、残余扫描 {PUA 0, 防 769, □ 2}、往返校验结果、候选处置
附件、缺口携带记录、产物登记（S3 哈希/字节、新 manifest
三元组）。公开侧只镜像计数与哈希（全文与逐条 old/new 不入
公开仓，沿 018-H 摘要登记先例）。

### 2.5 往返校验

只认 **origin 位点图逆复放**：正向全程逐字记录 origin，逆向
重建输入并比对哈希——逆复放至 444 点须 == `db8618c9…`、至
S0 须 == `00e2a7db…`。**朴素逆字符串替换禁用**（AP3）：统一
PUA 替换逆向多义（替换字在他处可预存），且 ocr-022 豁免
证明目标串预存真实发生，朴素逆替换必然产生假信号。

### 2.6 PUA 全核门（阶段一前置，fail-hard F10）

86/86 码位逐一见证复核并登记：逐码位 {codepoint,
replacement, 见证出处（独立见证 repo@commit + 位点）, 复核
结论}；U+E7E8 逐规则（4 规则 / 5 处）锚点复核。取全核不取
抽核（AP2）：应用使每条读法成为全部下游坐标与订正的承重
前提，且 524 处规模全核可行；任一码位缺登记，阶段一不得
启动。全核可作为应用批的 phase 0 子批先行落账。

### 2.7 Fail-hard 条件（F1–F10）与零部分应用

F1 冻结漂移（五文件哈希或 manifest 三元组不符，开工前中止）；
F2 阶段一逐码位计数漂移；F3 阶段一输出哈希不符 S1 钉值；
F4 阶段二任一条 old 轮次计数 != 1（不得改序/跳过/放宽锚）；
F5 目标预存校验失败或豁免使用集 != {ocr-022}；F6 444 检查
点不符 S2 钉值；F7 终局校验任一不符；F8 附件不完备（993
处置缺条、76 条 context 携带缺失且未登 limitation、RD-12
位点字与快照 old 不符、缺口未原样携带）；F9 写入纪律（写向
快照本体或 data/canonical/** ——两支脚本对 canonical 路径
自带拒绝，应用批不得绕过或改脚本放行）；F10 全核门未过。
全部产出先写工作副本暂存区，任一触发整批丢弃；正式产物只
在全链（含附件）通过后原子改名落位。**零部分应用含附件**
（AP5）。

### 2.8 产物形态与 manifest 换代

新增两件密封文件，与快照并存不覆盖：
`sanming_tonghui_applied_v1.txt`（S3 文本，1,342,682 字节）
与 `sanming_formal_application_report_v1.json`（应用报告）。

## 四、残余前置逐项路线

### 4.1 残余「防」769 处

实测工作量口径：S3 中 769 处、±6 字语境 769 个全互异——
不存在可批量合并的同文重复，逐处互校的最小工作单元就是
769。定性不变：「防」是多源汇讹字（「防代煞」已证伪），
**全局替换永久禁用**。逐处处置三种：confirmed_reading
（≥2 独立见证、含至少一纸本谱系见证，以校勘记形制登记）、
variant_parallel（谱系异文并列）、hold（证据不足，保留字
面登记未决）。路线：需求面优先（后续批次消费到的节先行，
018-F 两节处置 49 处、018-G 处置 15 处为已行先例），其余
按卷序以残余防归因批序列推进，逐批在台账登记
disposed/769；完成判据 = 769/769 有登记处置（处置不等于
改字）。坐标纪律：残余防定义在 S3 上，快照坐标的既有校勘
记经 origin 图映射，不直接套用偏移。未来某处获得 confirmed
订正时，只经新的应用版本（v2）进入，旧登记以订正事件追加。

### 4.2 12 条 reading_disagreement 见证互校

12 条全表见登记册（seq 361/385/450/612/616/784/824/853/
873/880/931/933；卷五 3、卷七 2、卷十 3、卷十一 4；old 字
为防 8、着 2、胤 1、玄 1；位点 12/12 direct 可锚，context
11 可锚 + seq 450 跨界；correction_id 全为 null）。
见证结构是**谱系对谱系**：四库谱系（kanripo/KR3g0042
@efe780a4、mikkokotila/Sanming-Tongshui @eb3cacbf）同读
historical_reading；现代转录谱系（NiuTrans @4e746ea9、
youngzs @aa7bc942、michiboo/Wikisource @5acdca06）读异字。
独立性口径：四库两家同属一个谱系、计为一个见证方（同
TJ-017.1 神峰先例）；现代三家的谱系独立性须逐条核实不得
假设（维基文库源出影印传统，与网络转录未必同源）。
判定标准：可择一，当且仅当 (a) 出现与两簇均独立的第三
谱系见证证实其一，或 (b) 逐条内证（文义/对文/韵律/术语
一致性）决定性成立并逐条登记；否则异文并列、应用文本保留
快照字。逐条独立判定，禁止以一条类推其余。逐条注记：
seq 450「䕶/获」两读文义皆通、内证不显然，预期并列；
seq 880「玄」三方三读（四库作𤣥为异体、快照作玄、现代作
元），属字形异文，与 TJ-017.1 清单 #5 的 EA20「玄」是不同
对象；seq 784「胤」四库作𦙍（异体）、现代作嗣（语义替换
读法）；seq 853/931「着」四库作著、现代作「者」疑转录
讹，内证较强但仍须逐条登记。默认处置（并列）不需要用户
裁定；只有未来 canonical 文本要求单一读法时才触发 UD-1。

### 4.3 unresolved_text_gaps 2 处

现状（manifest 在案，本批复核）：其一「谬□甚矣」——提议
「谬误甚矣」，证据为 sinan-app 现代转述本的释读，两家四库
转录见证均保留「謬□甚矣」；其二「王麟洲少□」——提议
「王麟洲少卿」，证据为中研院人物资料（王世懋擢南京太常
少卿）的履历旁证，不能证明本句缺字。两条状态均为
needs_base_text_evidence_do_not_apply；PUA 审计文件的
identified 两条与此恰对应；快照「□」恰 2 处、三阶段恒
为 2（本批实测）。处置（AP4）：应用批以 permanent_gaps
原样登记并逐字保留 □，提议读法只作提案字段、永不进入
应用文本；两缺口**只阻断整书 canonical 晋级**，不阻断
应用批与逐节晋级。重开条件唯一：出现底本级新证据（四库
影印原叶或独立刊本同位文字），以订正事件重开。

### 4.4 版本冻结登记

冻结时点 = 本批合并（E0294）。冻结锚：五件冻结对象文件级
SHA256 + 三阶段文本哈希 + 密封 manifest 三元组
（235 / 13,580,501 / `e5a590b4…`）。版本对应关系成组登记：
快照哈希 ↔ PUA JSON 哈希 ↔ 订正 JSON 哈希 ↔ 候选 JSON
哈希 ↔ 基线 blob `e6dab2c5…`，任一环被流水线再生成即整组
失效——应用批开工 F1 必失败，须先以订正事件更新本登记册
钉值并附再生成说明，禁止应用批现场换钉。冻结只及三命
五件；快照内其他作品的变动经 manifest 三元组在 F1 一并
检出。

## 五、晋级判定接口

### 5.2 应用批之后还剩什么

- **P1 终局化登记（余量）**：variant_preserve 47 条异文
  登记 + historical_only_hold 775 条历史读法定位登记，
  坐标换算至 S3，独立终局化批，复用应用批 origin 图。

  769/769 有登记处置。
- **P3 RD-12 见证互校批**：按 §4.2 标准逐条互校，预期
  产出以并列登记为主；仅当要求单一读法时触发 UD-1。
- **P4 TJ-018.3 决策包与台账裁定**：汇总应用报告、P1–P3
  状态、逐节校勘记（累计 383 条）与永久缺口，对 WBS
  TJ-018.3 验收口径（每个审核场景独立 Source/Section/
