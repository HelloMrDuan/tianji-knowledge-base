## 一、工作包完成定义（DoD）

**需求完成**：用户故事/页面/输入/输出/错误态/资料精度/知识边界都有链接；所需真实接口、视觉参考与原设计差异说明明确。

**代码完成**：真实后端/前端实现，若有必要更新现有 Source/Review/Rule/Golden；不能用 Mock 实际测算结果、假截图、随机分数或单纯拼 README 替代。

**安全完成**：公开包/浏览器响应不泄漏私有知识正文、路径、SHA、token 或敏感输入；管理操作有服务端鉴权和审计，个人资料可以明确清除。

**测试完成**：至少一个正常路径、一个拒绝/反例、一个边界路径；影响计算的必须有 Python+真实数据测试，影响 UI 的必须有真实浏览器 Playwright + 1440/390/360 视觉对比；第三方/AI 真模型评测不得以测试桩替代。

**集成完成**：当前 PR head 的公开 code/frontend/data gate 全绿；有知识或场景变更时私有 CI 固定同一 head 做完整 Canonical+真实 API/浏览器；合并后 main SHA 回归；失败查日志修复重跑。

**产品完成**：真实受控环境端到端验收（用户输入→响应→证据→错误→返回/删除），有环境/部署信息才能写“已发布”，否则最多写“已合并”。

**视觉完成**：必须同时提供原版 PR #87（图形语言）、#89（场景 IA）对应截图和新截图、逐项偏差说明与必要响应式差异；**不可凭开发者个人审美改风格**。没有设计视觉复核不能关闭 UI 任务。

## 十一、反跑偏暂停条件

- **视觉偏差**：未附 #87 原图对照，不能称 UI 改造“完成”；若首屏像普通财务仪表盘、背景变纯黑、专业排盘盖过生活问题，必须修回原设计。
- **知识不足**：当要输出旺衰、用神、真实交运、婚期、财运、梦境解释时，没有来源/具体条件/反例/冲突/Golden 就停止该结论的发布，不是停止所有可用结构展示。
- **隐私与版本风险**：静态网页或 API 透出内部来源清单、私有长引、服务端秘钥，或计算结果与输入年份不一致，必须阻断合并。
- **测试范围不足**：只有代码静态检查没有真实受保护 API/浏览器不能标为“已交付”；只有 Playwright Mock 不能宣称后端业务完整。
- **临时想到的新功能**：先在台账中提交影响和优先级变更，除紧急安全修复外不插队 TJ-030 专业扩展。
- **不做假计划工期**：每个工作包以可复现产物和门禁推进；若受到证据、服务器或权限阻塞，标记并切到同一产品里依赖满足的下一项，而不是无止境补无关文档。
