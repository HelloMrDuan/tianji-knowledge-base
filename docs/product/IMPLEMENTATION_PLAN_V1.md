# 天机命理平台｜分阶段实施计划 V1.0

> 对应[产品总纲](PRODUCT_MASTER_PLAN_V1.md)；每一项对应 [执行台账](EXECUTION_LEDGER.md) 的 `TJ-xxx`。  
> 本文件按**依赖与验收**安排顺序，不凭空承诺日历工期。2026-10-11 起生效；以公开、私有仓库真实 SHA 和 Actions 为验收依据。

## 0. 项目实施方法

- **只设一条主产品线**：生活场景可用 → 八字/大运/梦境知识支撑 → 桃花/事业/合盘/人生总览解释 → 部署运营。不要在主线未闭环时转去随机补专业工具。
- **双仓职责**：公开仓库只放业务代码、前端、非敏感测试、公开安全文档；私有仓库负责受控知识内容、Canonical/Quarantine、详细来源校勘与全量私有验收。原典未审核/权利未明确，留 private research，不进入公开静态包。
- **按小批 PR**：最小可交付＝源码更改 + 正/负/边界测试 + 真实 API 或浏览器用例 + 私有知识验收（若涉及知识）+ CI + 合并结果。纯资料审查必须提供明确待审核证据记录和下一步执行入口，不能被统计成“产品完成”。
- **合并门禁**：公开 `code/frontend-build/gate-public-data` 全绿；涉及知识/算法/场景必须由私有 runner 以固定公开 head SHA 核验完整原始 235 文件清单（以届时实际数为准）、整个 Python 回归和受控实时接口/浏览器；公开主分支合并后再做最终组合 SHA 回归。错误须读日志修复重跑。
- **发布门禁**：上线属于另一状态；须有受控环境运行结果、真实入口 URL、权限与网关、日志/监控、回滚以及用户闭环。不能用 PR 合并代替部署验收。
- **统一状态**：待做 / 进行中 / 已提交PR / CI待验 / 已合并 / 已部署验收 / 阻塞。不得因为测试数字增加擅自标注“完成”。

## M1｜普通用户受限 MVP（第一个真实产品交付）

| ID | 任务 | 交付与验收 |
| --- | --- | --- |
| TJ-006 | 八字/日周月年跨场景资料、时区、日期、版本统一 | 浏览器本地保存、清除、多场景实际后端结果一致；无效日期/时区明确拒绝；不静默套示例 |
| TJ-007 | 11 个入口的“完成一次”体验 | 输入→请求→页面结果/出处→异常状态→下一场景，既有后端能力必须真实使用，禁止虚构牌面 |
| TJ-008 | 首页与结果层级打磨 | 古风风格统一、加载明确、响应移动端、证据按需展开、未覆盖和研究边界醒目；用户不用读技术 JSON |
| TJ-009 | 背景音乐和访问体验回归 | 原创音轨按用户动作播放，路由无中断、暂停/音量可控，自动播放受限，刷新/禁用音频行为可预期；浏览器、移动端回归 |

**阶段退出**：11 个入口都可做一次有价值、明确限界的**真实限定流程**；不宣称每个都能给吉凶预测。以 Playwright 视频/trace、真实 API 和可复验路径为证据。

## M2｜八字详批知识与裁决（核心算法主线）

| ID | 任务 | 知识/算法依赖与验收 |
| --- | --- | --- |
| TJ-010 | 月令、通根、透干、根可用性与异文复核 | 对照现有 C 级短引、条件、反例；分日司令冲突保留独立 Variant；无证据不填数值权重 |
| TJ-011 | 旺衰明确充分条件扩围 | 以当前 `bazi-strength-adjudication-v1` 有界研究为起点，对每新增条件给来源逐字定位、条件、反例、冲突、Golden，支持 strong/weak/**indeterminate**；未审五行/根型不类推 |
| TJ-012 | 格局候选与判定门禁 | 正官/印绶等已存在研究候选作为输入；明确真假、成败、月令/合冲边界；在已审范围之外只展示候选，不能称格局已定 |
| TJ-013 | 喜用体系按流派分别治理 | 调候/扶抑/病药/格局取用不混为一套；每结论绑定已验证旺衰、格局、原典、反例，否则明确不可判断 |

**阶段退出**：先有**可核验的限定版旺衰/格局**及弃判；不能将“算法输出强弱”当作“全八字详批完成”，也不可抢先向页面开放未审喜用神。

## M3｜大运起运、交运与岁运作用

| ID | 任务 | 知识/算法依赖与验收 |
| --- | --- | --- |
| TJ-014 | 取运顺逆的原典流派矩阵 | 年干阴阳与历史传统角色口径显式用户选择，来源和差异逐一审；不得依据用户名或现实身份推断 |
| TJ-015 | 十二节边界/历法/时区可靠性 | 固定历法软件的交节秒值重放、不同版本/独立历法对照、零距离、跨年/历史时区；偏差公开记录，未经独立核准不得宣称天文准确 |
| TJ-016 | 三日一年与起运岁数口径 | 按具体来源分离时日余数/历年换算、实虚岁、取整、交节当秒；用实数案例及反例审定 Variant。现有 `bazi_dayun_simulation.py` 仅研究，不能换字段名冒充真交运 |
| TJ-017 | 交运日期、十年序列与流年联动 | 依赖 TJ-014~016、M2；前后台复现边界金例，来源+冲突+错误范围完整；全部前置校核通过才启用对应有限解释 |

**阶段退出**：仅在方法、历法、流派和授权范围都获验后，计算具有明示方法的**限定交运时间**。其余模式仍研究/弃判，不制造通用“精准交运”。

## M4｜解梦内容、溯源、语义识别

| ID | 任务 | 知识/产品依赖与验收 |
| --- | --- | --- |
| TJ-018 | 传统梦境来源审核与合法入库 | 从真实固定 RAW/Quarantine 核对版本、许可、逐字短引与位置；整书不能批量晋级；继续使用现有 Source/Review/Rule 模型 |
| TJ-019 | 扩展常见梦境场景，但只按具体动作审核 | 当前已审 10 个场景为基线；“被追、考试、怀孕、故人、婚礼、工作”等未获严格出处的主题只显示“暂无审核解释”，每条新增独立证据/反例/Golden |
| TJ-020 | 有界语义检索、纠错与解释边界 | 主体、动作、否定、转述、时间顺序、并列梦象、代词边界；正例、反例、精确输入片段与引用测试，未知语义弃判；不把字符串命中当万能 NLP |
| TJ-021 | 用户能读懂的解梦结果页 | “梦中原话→对应场景→古籍短引→限界→未知细节”可追溯；仅在经过真实模型语义评测后再考虑 AI 生成式文字，不能宣称传统释义能诊断未来 |

**阶段退出**：可解释的命中、有拒答的覆盖，主题数量增加必须伴随审核条目和真实测试，而不是一份梦境名称列表。

## M5｜桃花、事业、合盘与人生总览的综合交付

| ID | 任务 | 依赖与验收 |
| --- | --- | --- |
| TJ-022 | 桃花姻缘条件解释 | 基于年/日支咸池、配偶宫/星与已审原局和岁运规则；分视角说明，没有来源绝不生成“正缘年份” |
| TJ-023 | 事业财运跨规则解释 | 财官食印比劫位置+已核作用条件+流年/大运，生成有限事实、条件和来源；不能把计数换算财富指数 |
| TJ-024 | 合盘双向聚合 | A/B 各自结构、4×4 跨柱矩阵、冲突/证据、不同传统角色选项分离，禁止百分比、肯定性婚恋结论 |
| TJ-025 | 人生总览证据聚合 | 每一段事实显示来源子场景/Rule/Evidence；跨规则条件不足时弃判；“结构版”和“限定解释版”区分，避免汇总时凭空创造新结论 |

**阶段退出**：普通人能从同一张总览看到来源清楚且不互相矛盾的实际结构；没有经验证据就不生成更高级结论。

## 按此顺序实际开工

**第 1 批：TJ-002**，复核已全部成功的私有 #50 双回归与正确 head SHA 后完成合并，并更新台账；不得在这批顺手新建术数功能。  
**第 2 批：TJ-004**，对 11 个前台入口逐个执行真实 API/浏览器“成功+异常”验收并产出可执行失败清单。  
**第 3 批：TJ-003 与 TJ-005 的前置检查**，确认受控服务端、公开泄露面及部署路径。  
**第 4 批起：** 根据 TJ-004 的真实失败清单先修 MVP 闭环，再按 TJ-010～017 / TJ-018～021 的知识依赖推进，不随意切换到专业工具。

TJ-010～017 与 TJ-018～021 可以在严格独立来源门禁下并行研究，但不能以此改变核心主线顺序。各阶段只有里程碑退出标准满足才标记“可用”；没有任何依据时正确状态是“阻塞/待审”。

## 每个 PR 的强制验收模板

```text
任务 ID / 里程碑：
用户实际变化（或阻塞依赖）：
修改源码与公开/私有影响：
现有证据 + 新证据 Locator/Version/License/Variant：
正例、反例、边界 Golden 和研究弃判：
公开 PR/head SHA 与 CI：
私有 PR/固定公开 SHA 与完整 Canonical/浏览器 CI：
合并的两个 main SHA：
部署地址/真实运行验收（没有就写“未部署”）：
新的剩余缺口 / 台账状态：
```

若只有文档/代码 PR、只有 Mock、只有部分测试或只有 CI 队列，必须注明是“未达成发布门槛”。产品文案不能把 `research_only`、`production_limited` 和 `production` 混写。
