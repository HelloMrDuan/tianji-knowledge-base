# 天机平台｜逐页功能、交互与视觉验收规格 V1.0

> 先读[最初设计基线](ORIGINAL_DESIGN_BASELINE_V1.md)。本规格不是重新设计页面，而是把 **#87 原版古风视觉 + #89 生活场景导航 + 当前已验证的真实引擎**转换为可开发、可测试、可审查的逐页要求。  
> 页面 ID `UI-xx` 绑定[细化实施计划](DETAILED_DELIVERY_BACKLOG_V1.md)，每项 PR 必须列出该 ID 及真实浏览器链接。

## 0. 全站统一组件合同

### 0.1 页面骨架（每个页面必须遵守）
- `GlobalHeader`：原“天机”品牌印记/副标、生活场景导航、记录与二级专业入口、古风音乐按钮。响应式结构沿用 #87；首页导航语义以 #89 为准。
- `InkHero`：纸色背景、宋体主标题、水墨远山、铜色题签；**不得**把专业术数表单放到首页首屏视觉中心。
- `ScenarioCard`：场景名/简短用途、输入成本、实际状态、可做/不能做、唯一可执行 CTA；支持键盘焦点，真实未开放时不可显示“立即测算”。
- `InputPanel`：逐项字段标签、日期格式、可理解的时区与隐私说明；仅收场景必须的数据、避免出生时间不详时暗设中午。
- `ResultShell`：事实摘要、结构或文化短引、证据折叠、Variant/范围、异常反馈、下一步场景；任何指标没有明确 Rule/Evidence 均为空，不填 60 分/好运百分比。
- `EvidenceDrawer`：**最小必要的审核短引** + 古籍名/章节 + 来源等级 + 适用限制，不输出原始私有路径/hash/全量 Trace/RAG。
- `InlineStatus`：未输入/loading/success/partial/unresolved/empty/error/offline/unauthorized 状态各有中文文案和适当操作，不能用假占位结果盖住错误。
- `ResponsiveNav`：桌面 header + 390/360px 底部导航；真实用户路径不因横向溢出、中断焦点或浮层遮住提交按钮而断裂。
- `AdminLayout`：独立浅灰白工作台、240px 侧栏、75px 顶栏、表格/抽屉/详情，绝不加载前台音乐/水墨背景。

### 0.2 通用功能状态与验收

| 状态 | 应有表现 | 不允许 |
| --- | --- | --- |
| 初始 | 说明当前能算/不能算和需提供哪些数据；不预先暴露用户出生资料 | 自动提交样例、生成虚假的个人结果 |
| 入参非法 | 字段级错误、焦点定位、不发 API | 静默改日期、将未知时刻设为 12:00 |
| 请求中 | 清楚的进度反馈、按钮防重复提交、可返回 | 先展示模拟测算结果 |
| 成功 | 真实 API 对应数据、适用 Variant/日期、必要证据、限制 | 未审吉凶、任意整合“指数” |
| 部分/弃判 | 已验证结构保持可见，不具备的解释写“暂无足够依据” | 隐藏缺口或让模型补齐 |
| 无匹配 | 展示为何无结果、可更正什么、下一步 | 把只出现“蛇”解释成“蛇咬人” |
| 服务失败 | 错误原因分类、恢复资料、可重试 | 以缓存样例冒充在线计算 |
| 禁止访问 | 不泄漏管理信息，提供恰当提示 | 在浏览器 console 打印令牌、私有来源、完整 Trace |

### 0.3 统一资料与年度状态
- `birthProfile.ts` 负责用户主动提交后的有效出生日期/时间的本机复用和明确清除；在页面展示本机保存说明。合盘 A/B 资料不得随意写入普通个人出生档案、也不可无授权长期保留第二个人资料。
- `targetYear.ts` 统一可选年份，结果和实际请求必须相同；日期、时区与起年边界在界面标明；年份切换必须重新计算而非只改标题。
- 共享资料只代表当前浏览器偏好，不等于“注册账号 / 云同步 / 隐私完善”。无登录时不得显示跨设备可恢复。
- 当前场景 API：`POST /api/v1/public/execute`（八字、六爻）、`POST /api/v1/scenarios/public`（生活计算场景）、`POST /api/v1/dream/culture`（已审梦境文化查阅）；管理员使用独立受保护 API。
- API 返回中断/重试/超时、输入与响应目标年不一致、Evidence 缺失、凭空添加字段均要有自动化反例。

## 1. 首页与全站功能

### UI-00｜首页 `/`（**最先完成视觉差异验收**）
**原参考**：#87 `home-desktop/mobile`（水墨/纸色/古风布局）＋ #89 `home-desktop/mobile` 和 `HOME_ADMIN_IA.md`（生活场景阅读次序）。

**桌面布局**：品牌导航 + 水墨 Hero（左文右水墨）→ 一事占问主 CTA、桃花/事业辅助 CTA → 今/周/月/年时间带 → 11 个场景入口 → 有真实记录才出现“继续上次” → 计算/规则/典籍/限制的可信说明 → 7 个专业排盘入口 → 底部版权与文化局限性。

**手机布局**：首屏题签、标题、水墨露出、主 CTA 不折断；导航采用“首页／场景／记录／我的”设计语义，收藏进记录；不能为改变导航而失去 `/favorites` 既有可达性。两列/单列卡片按真实宽度适配，音乐按钮可用但不挡标题。

**关键行为**：11 场景均可见，完整能力不足时有“结构版/文化查阅”等诚实状态；时间带跳转日周月年且携带合法资料；点击 CTA 到真正场景页；未登录与未保存时显示真实空态。

**明确差异**：当前 `HomePage.tsx` Hero 主 CTA 是“生成人生总览”；#89 原定是一事占问，必须出具差异对照并按设计基线调整，不是默默保留新首页。事业财运可以**两张入口、一份核心报告、两种视图**，不增建两份相互矛盾的计算。

**验收**：11 卡片 + 7 专业入口均真实可导航；无失效链接、无隐式 API；1440/390/360 截图与参考并列；可读性、音乐、键盘与底部导航回归。

### UI-01｜全局导航、历史、收藏、我的 `/history`、`/favorites`
原参考 #87 history/favorites 桌面和手机图。保留搜索、筛选、空状态、收藏和返回，但**旧固定 DEMO 不得伪装为用户历史**。如果没有真实用户存储服务，只提供明确标记的本机记录/样例区；不做虚假的登录、云端同步。若新增“我的”，需要列出资料、记录、收藏、清除及隐私入口；旧地址重定向与深链接兼容。

**验收**：无记录空态、过滤无结果、取消收藏、刷新持久性边界、隐私清除、移动端从主页到记录操作可走通。

### 2.1 生活场景页面的视觉细则

**UI-02 八字**：沿用 #87 `/bazi` 四柱图的垂直比例、输入卡和古风标题，转成真实四柱时应仍是年/月/日/时横向视觉骨架；移动端可栈叠，不减少任何一柱数据。专业详细证据折叠，概览显示“已审核结构/未完成解释”。

**UI-03~06 运势**：都沿用纸色/深青/铜金，**日历属于真实日期窗口，解释必须是证据绑定的事实**。今日紧凑，周是 7 日序列，月是表格/按日期可展开，年突出可选年份。不得为了吸引用户加虚假的幸运色、分数、吉日或动效预测仪表。

**UI-07~09 桃花/事业/合盘**：三类都先显示一份普通用户可读的“条件摘要”，再按需要展开十神/支关系/原局差异；合盘双色对照可使用同一古风中性色系差异，不变成粉红恋爱测试或彩色匹配雷达。若字段未审，写明“结构信息，不是现实保证”。

**UI-10 一事占问**：保留原版六爻盘的 **六爻从下到上、静动分明、移动完整盘面**；一事占问标题/入口生活化，专业盘面置于展开层，不删除任何真实信息。用户输入具体事项不可被静态盘替换。

**UI-11 梦境**：更偏叙述阅读、段落与书卷卡片；引用栏显示古籍短引与原话的对应关系，未命中要真诚说明“暂无经核验的条目”。不能显示模型正在深度解读然后返回固定模板。

**UI-12 人生总览**：多节事实叙事卡来自四个真实子场景，**每个标题保留来源**；不把四条资料拼成虚假“人生优劣评级”。至少一次真实跨页面跳转与年份一致性测试。

### 2.2 所有生活页的交互矩阵

| 场景动作 | 必须表现 | 重点边界 |
| --- | --- | --- |
| 从首页进入 | 复用古风 Header、正确激活导航、保留有效本机资料 | 未授权不能带入别人的信息 |
| 修改输入 | 立即把旧结果标为不适用或清除；提交后才出现新结果 | 避免“只换标签未重算” |
| 计算按钮 | 防重复点击，loading 可见，响应对应真实请求 | 旧请求晚回不可覆盖新数据 |
| 展开古籍 | 只显示该结果获审的短引/出处/范围 | 不出内部完整 Evidence 路径或长引 |
| 出现流派冲突 | 分方法输出和差异，不自动加权投票 | 不暗自选唯一“最准” |
| 部分已支持 | 真实结构继续显示，缺口独立表述 | 不把部分可用显示“完整算命已完成” |
| 失败/断网 | 提示可重试，保存未提交文本在当前页面 | 不使用演示图兜底冒充已计算 |
| 切换手机布局 | 全部内容可垂直读、按钮可触达，盘面支持折叠或横滚 | 不以字体极小来解决溢出 |

- 第一阶段：**只读真实数据**（已可受保护查询才标可用）+ 明确角色/身份/日志；界面无保存功能时保持禁用。
