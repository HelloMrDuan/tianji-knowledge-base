# 天机命理平台｜产品总纲 V1.0

> 版本：2026-10-11 · **后续开发统一方向基线**  
> 文档导航：[分阶段实施计划](IMPLEMENTATION_PLAN_V1.md)｜[执行与验收台账](EXECUTION_LEDGER.md)  
> 注意：本文件是项目管理基线，**不是知识审核授权、功能完成证书或上线声明**。

## 1. 核心产品定位

**做一个普通人愿意每天使用的古风传统文化互动平台，而不是一个只陈列术数术语和古籍的研究网站。**

完整体验应为：**选择关心的生活问题 → 输入出生资料 / 梦境 / 一件事 → 调用真实的确定性算法或已审文化检索 → 得到直观的聚合结果 → 查看可信出处、适用条件及限制**。

核心要求：入口有吸引力、界面古风好看、音乐和交互完整；知识库提供依据，不能靠 AI 凭空编造；确定性盘面与文化释义、流派候选与已审核结论必须分层。文化体验不保证现实吉凶，更不能代替医疗、法律或投资建议。

### 用户优先级
1. **首次用户**：能看懂八字基础、桃花、事业、梦境、一事占问，少填资料，结果不是技术 JSON。
2. **回访用户**：能复用本人出生资料，看日/周/月/年度结构，不必重复排盘。
3. **探索用户**：查看合盘与人生总览，理解多个场景之间的真实关联，不靠分数欺骗。
4. **管理员**：有权限地审核来源、规则、证据、流派差异、模型/发布状态；私有原文不面向前台公开。

## 3. 前台必须保留的 11 个生活场景

| 产品 | 已有真实能力 | 核心缺口 / 当前输出边界 |
| --- | --- | --- |
| 八字基础档案 → 八字详批 | 四柱、日主、十神、藏干、有限月令/通根/透藏结构与来源 | **通用旺衰、格局、喜用神、起运交运、组合判读**未闭环 |
| 今日运势 | 当日干支、十神、咸池、地支冲合害结构 | 不是事件吉凶或宜忌 |
| 本周运势 | 周一至周日 7 天结构及频次 | 不是完整七日运势判断 |
| 本月运势 | 公历自然月每日日结构与统计 | 非节气流月完整解释 |
| 流年/今年运势 | 自选年份年干支、十神等 | 缺原局×大运×流年的条件作用 |
| 桃花姻缘 | 年支/日支两套咸池，原局与目标年匹配 | 不能直接断正缘、婚期、关系好坏 |
| 事业财运 | 财官食印比劫位置、流年结构 | 未形成经审条件解释和事件概率 |
| 缘分合盘 | 双人四柱、双向十神、冲合害、三合、证据矩阵 | 不能推出适配百分比、婚期或分手预测 |
| 一事占问 | 六爻录入、确定性起卦、动变与已审核证据 | 不用万能模板生成应期或现实保证 |
| 传统梦象查阅 → AI 解梦目标 | **10 个已审具体文化场景**、真实检索/短引/拒答、有限复句语义 | 完整“AI 解梦”仍 `NOT_BUILT`，大量梦象没有经审出处，不能编造 |
| 人生总览 | 一次输入聚合八字、年度、桃花、事业四条真实结构 | 暂为“人生结构总览”，高级跨规则解读仍 `BLOCKED_ADVANCED` |

**展示形态目标**：每个结果页要有一屏看懂的摘要、关键事实、来源出处、未覆盖/冲突提示、下一步相关入口；允许查看专业详情，但无需普通用户理解 Trace/Rule ID。把古籍全文管理从消费者页面移到后台。

## 4. 专业工具与管理后台：明确第二优先级

- 专业页共 7 个导航领域：八字、六爻、奇门、紫微、六壬、周易、风水；其中五个专业工具在产品覆盖报告为 `PARTIAL`，专业输入/结果“设计预览”不得冒充完整实时计算。
- 后台已有 Classic、Chapter、Term、Source、Rule、Evidence、Conflict、Variant、Prompt、Provider 和解梦研究页面，以及部分受保护只读管理 API。后续逐页核查真实数据和权限；**只读接口与静态菜单不等于可编辑管理平台**。
- 现有古风水墨页面、`InkLandscape` 和 `MusicPlayer` 已落地；背景音乐默认关闭，用户主动播放、暂停、调整音量，页面间不打断。后续统一手机端体验、加载性能与无障碍。
- 除上述主线以外的塔罗、更多门派、全网无筛选采集等，列入远期候选，不得挤占核心体验与知识审核。

## 5. 后端、知识资产及安全总原则

### 计算与知识
```text
用户输入 → 参数/时区/日期校验 → 确定性 Calendar/Scenario/Engine
        → RuleMatch + Evidence + 冲突/限制 + Golden 回归
        → 公开响应最小化投影 → 读得懂的页面
                     ↘ AI（仅在单独校准和发布许可后）
```

统一沿用 **Source → RAW → Quarantine → Review → Canonical → Term/Rule/Variant → Evidence → Golden → Scenario**。任一缺环不可由 prompt、评分公式或现代开源实现填补。

**旺衰**：只认可已有明确范围的研究充分条件；未能裁定就 `indeterminate`。**大运**：节差与模拟日期目前只属研究，不是已审核正式交运时间。**梦境**：10 个已审核特定场景不等于任意主题；同一动物不同动作不能互换，未审主题只做输入观察/弃判。**桃花/事业/合盘**：结构命中不是恋爱、财富、性格或人生概率。

### 私有与上线
- 正式知识正文、内部原典定位、SHA、完整 Trace、秘钥、服务端生成制品必须保留在受控私有环境；前端只取审核允许的必要短引。
- **公开仓库 HEAD 和历史仍有知识衍生材料**；建设私有仓库不自动使既有公开数据撤回。以 `docs/PRIVATE_KNOWLEDGE_CUTOVER.md`、`docs/PUBLIC_DATA_SURFACE.md` 为迁移门禁。
- AI 公开解释必须通过**真实模型连接、固定与对抗测试、引用准确率、人工抽审和按领域发布**；未通过就保持关闭，不能用 Mock 成绩宣布上线。
- 健康/投资/法律等高风险实际决策不提供预测性或替代专业建议的结论。

## 6. 开发的阶段目标（入口先行、知识随后闭环）

1. **M0｜基线与安全**：一个计划、一套任务编号、真实双仓 CI、敏感资产检查、可重复部署边界。
2. **M1｜生活产品受限 MVP**：先让 11 个页面的真实 API、状态、引用、失败/无证据、共享资料和古风体验完全一致；给普通用户一套真正可体验的限定功能。
3. **M2｜八字判读主干**：依次推进月令与作用条件 → 范围明确的旺衰 → 格局分歧 → 分流派喜用体系，先形成可审的有限结果，不做虚假“全能命书”。
4. **M3｜大运与时间轴**：顺逆流派、节界/历史时区、三日一年等换算、实虚岁与零边界逐项审核；获得证据授权后再接入原局与岁运。
5. **M4｜解梦内容与检索**：审核更多合法来源/具体条目，扩充实体-动作-主体-否定/复句识别；准确拒答优先于覆盖数量。
6. **M5｜跨场景可读解释**：事业财运、桃花、合盘、人生总览在已审旺衰/行运/关系规则之上做有限聚合和溯源，并把结构版与解释版清晰区分。
7. **M6｜上线与治理**：后台权限、发布流水线、私有服务端部署、观察指标/回滚/成本、AI 实测与安全评审。
8. **M7｜专业扩展**：五类专业工具按用户需求及证据成熟度逐项扩展，保持主场景优先。

各阶段的**任务、依赖、验收口径及先后顺序**见 [分阶段实施计划](IMPLEMENTATION_PLAN_V1.md)。

## 7. 防跑偏硬规则

1. **先有台账任务编号再动代码**：每个 PR 必须标注 `TJ-xxx`、用户感知结果、代码位置、证据、反例、真实 CI；未在计划内的需求先走变更控制。
2. **每批小而完整**：一个用户功能或一个明确阻塞依赖、附真实测试和验收；不以新增文档/研究页计用户交付。
3. **三种状态不得混用**：`代码已写` ≠ `双仓 CI 全绿` ≠ `已合并部署并可让用户访问`。以实际 SHA/PR/Actions/运行时结果记录。
4. **有依据才解释**：无 Source/Review/Variant/Rule/Evidence/Golden 时保持研究或弃判；《三命通会》等未审核材料不得提升为公开生产知识。
5. **禁止伪造出货量**：通过 524 项回归不是 16 个产品完成，也不是专业 AI 质量证明。
6. **优先级不随聊天临时漂移**：紧急修复可优先，但必须在台账写清风险；其他新增事项先改计划再开发。
7. **阶段验收看用户行为**：用户输入 → 后端调用 → 结果与出处 → 异常与隐私 → 真实浏览器/受保护 API → 才算一个交付。

**下一步动作应以 [执行台账](EXECUTION_LEDGER.md) 的未完成且依赖已满足的最高优先级任务为准，而不是随意新增批次。**
